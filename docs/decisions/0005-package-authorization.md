# Package authorization

Status: proposed · Updated: 2026-09-20 · Implementation: not implemented

## Context

Submission authority must identify the exact answers and artifacts used.

## Decision

The platform should use exact-package authorization as the worked default. It should preserve accepted previously authorized automation; an applicable policy may authorize the package without another manual pause.

## Alternatives considered

Mandatory manual approval for every submission; bounded live changes under recorded policy.

## Consequences and open work

Changed packages need a new authorization decision. Bounded live edits, ATS evidence, and reapplication rules remain open.

[Owning design or study](../domain/applications.md). This record extracts the disposition documented in the original September 19–20 proposals; it does not assert new implementation or provider validation.
